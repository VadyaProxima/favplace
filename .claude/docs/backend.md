# Backend — api-deeep-app

Location: `~/Documents/projects/deeep/api-deeep-app`

## Key Files

| File | Purpose |
|------|---------|
| `PageCreateExecutor.php` | Entry point: receives template UUIDs, starts the pipeline |
| `PageContentDataCollector.php` | Collects data: CMS keys, project/audience context, text_template |
| `PageTextPromptBuilder.php` | Builds system + user prompt for LLM |
| `CmsKeyExtractorService.php` | Parses template HTML → list of `CmsKeyInfo` (key, element, placeholder, parent/children) |
| `TemplateImageExtractorService.php` | Reads `images` from template.json (priority) or parses `data-cms-image` from HTML |
| `GeneratePageContentHandler.php` | Sends prompt to LLM, parses JSON response |
| `HtmlTextInjectionService.php` | Injects text into `[data-cms-key]`, `[data-cms-link]` |
| `HtmlImageInjector.php` | Injects `src` into `[data-cms-image]`, `[data-cms-logo]` |
| `AssemblePageHtmlHandler.php` | Final assembly: text + images → full HTML |

## Generation Pipeline

```
1. PageCreateExecutor        — receives list of template UUIDs (not random selection!)
2. PageTemplateComponentService — loads templates from DB by UUID
3. GeneratePageContentHandler  — generates text via LLM
   ├── CmsKeyExtractorService     — parses [data-cms-key] and [data-cms-link] from HTML
   ├── TemplateImageExtractorService — parses images from template.json
   ├── PageTextPromptBuilder      — builds prompt with XML structure
   └── TextGenerator.generate()  — calls LLM API
4. GeneratePageImageBatchMessage — generates images (async)
5. AssemblePageHtmlHandler       — injects text + images into HTML
```

For one-off backend file uploads use the open `POST /api/upload`; JWT is not required:


## How Backend Reads template.json

```json
{
  "text_template": "...",          // → passed to LLM as section_instructions
  "volume_restrictions": "...",   // → passed to LLM as volume_restrictions
  "images": [
    {
      "key": "hero.image",
      "ratio": "16:9",
      "description": "...",        // → prompt for image generation
      "negative_prompt": "...",
      "remove_background": false   // → true for logos/icons, not generated by SD
    }
  ]
}
```

## CMS Attribute Handling

| Attribute | LLM generates text? | Who injects | Notes |
|---------|:---:|---|---|
| `data-cms-key` | ✅ | `HtmlTextInjectionService` | Supports parent-child nesting |
| `data-cms-link` | ✅ (only if not image/logo-only) | `HtmlTextInjectionService` | Skipped if contains only data-cms-logo or data-cms-image |
| `data-cms-image` | ❌ | `HtmlImageInjector` | src = URL of generated image |
| `data-cms-logo` | ❌ | `HtmlImageInjector.injectLogo()` | src = project.preset.logoFile |

### Important: image-only links are skipped
Backend (`isImageOnlyLink()`) **does not generate text** for `data-cms-link` elements that:
- Contain `data-cms-logo` → this is a logo wrapper link
- Contain only `data-cms-image` without text content
- Are icon-only (SVG/`<i>` without text)

`build-site.mjs` implements this analogously — looks for the pattern `data-cms-link="key">\s*<img data-cms-logo`.

## Static Image Asset Upload

Use this flow when a template must hardcode a stable backend-hosted asset URL, for example curated icons in `illustration-refs`. This is separate from image generation config in `template.json`: after uploading and hardcoding the returned URL in `src`, remove the corresponding generated image slot from `images[]` so backend does not generate that asset from metadata.

Keep `data-cms-image` on the `<img>` when the editor must still allow selecting and editing the image element. The static `src` is the default value; `data-cms-image` is the editable slot marker, not by itself a reason to keep generation config.

Endpoint:

```http
POST https://api.snapbuild.ru/api/upload
Content-Type: multipart/form-data
```

Authorization is not required for this endpoint in the current Snapbuild production flow. If a token is supplied and expired, the backend returns `401 Expired JWT Token`; without `Authorization`, valid multipart uploads are accepted.

Required multipart fields:

| Field | Value |
|---|---|
| `file` | Binary file |
| `fileName` | Original display filename, for example `TG cover_short.png` |
| `profileId` | Storage profile, for example `illustration-refs` |

Example:

```bash
curl -X POST "https://api.snapbuild.ru/api/upload" \
  -F "file=@/path/to/TG cover_short.png" \
  -F "fileName=TG cover_short.png" \
  -F "profileId=illustration-refs"
```

Validation check: an empty unauthenticated `POST /api/upload` currently returns `422 Form data is not valid` and reports `fileName`/`profileId` as required, confirming the route exists and validates form fields.

## Parent-child in Text

Backend supports nested CMS keys:

```html
<p data-cms-key="cta.subtitle">
  [Join over <span data-cms-key="cta.subtitle--bold">[10,000]</span> customers]
</p>
```

LLM receives:
```
- key: "cta.subtitle", has_children: ["cta.subtitle--bold"]
- key: "cta.subtitle--bold", parent: "cta.subtitle"
```

And generates:
```json
{
  "cta.subtitle": "Join over {cta.subtitle--bold} satisfied businesses",
  "cta.subtitle--bold": "2,500"
}
```

`build-site.mjs` does **not support** this — Ollama receives both keys without the link between them.

## Template Selection

**Backend does not select templates randomly.** The frontend passes a list of UUIDs, the backend loads them by UUID.

→ The `brand_specific: true` flag in template.json **does not affect the backend** — only `build-site.mjs`.

Template filtering for brand-specific templates in the UI requires a frontend change (not backend and not template.json).

## Prompt Structure

Backend builds an **XML-structured prompt** with:
- `<role>` — copywriter role
- `<rules>` — length rules (h1 < 80 chars, button 2-5 words, etc.)
- `<nested_element_rules>` — parent-child rules
- Tone of communication (from project settings)
- Localization region
- Reference documents
- VPC (Value Proposition Canvas) — pains, gains, jobs-to-be-done
- `<placeholders>` — list of CMS keys with element, placeholder, parent/children

`build-site.mjs` uses a simplified prompt without VPC and tone — this is fine for a test tool.
